# GiveTap — Technical Build Specification
### Contactless charitable-giving platform · agent build brief

> **Read this first.** This document is the source of truth for **structure, data, API, and behaviour**. It does **not** specify visual design — the **UI kit and branding come from Claude Design** (tokens, components, screens). Your job: implement the architecture below and render it using the delivered design kit. **Do not invent your own visual language.** Where a screen needs a component, use the kit's component; if one is missing, follow the kit's tokens and patterns to build it.
>
> Split: **Frontend = SolidJS.** **Backend = Elysia (Bun) + Turso (libSQL) + Drizzle ORM + BetterAuth.** Keep them decoupled — the web app talks to the API only through a typed HTTP client.

---

## 0. Product in one paragraph

Two surfaces joined by one object — a **campaign**. Operators sign in to an **admin console** (role-based) to create/manage campaigns and monitor giving live; the public uses a fast, branded **donor flow** to give (payment **simulated**). Each campaign auto-publishes a branded public page at `/c/:slug`, also usable in `/kiosk/:slug` collector mode (a volunteer's phone, auto-resets per donor). Money is recorded in the app and reconciled against a **mock payment processor**. Real NFC and real card charging are **out of scope**.

## 4. Data model (Drizzle, SQLite dialect)

Conventions: **all money is integer minor units** (`amountMinor`, e.g. €25.00 → `2500`) — never floats. Currency is ISO-4217 (`"EUR"`). IDs are `text` (cuid2 or `crypto.randomUUID()`). Timestamps `integer({ mode: 'timestamp' })`. Booleans `integer({ mode: 'boolean' })`. JSON via `text({ mode: 'json' }).$type<…>()`.

### 4.1 Auth tables — generated
Run `bunx @better-auth/cli generate` (Drizzle adapter, provider `sqlite`) → produces `user`, `session`, `account`, `verification`. The **admin plugin** adds `role`, `banned`, `banReason`, `banExpires` to `user`. Add a custom field `organizationId` via `user.additionalFields`. Do not hand-edit generated tables except via config.

### 4.2 Domain tables (`schema.ts`)

```ts
organization      // charities / tenants
  id            text pk
  name          text
  slug          text unique
  createdAt     timestamp

campaign
  id            text pk
  organizationId text -> organization.id
  slug          text unique                // /c/:slug
  name          text
  cause         text                       // category
  description   text
  story         text nullable
  targetMinor   integer                    // in `currency`
  currency      text                       // base currency of the campaign
  status        text  // 'draft'|'active'|'paused'|'ended'
  brandColor    text                       // hex, feeds --brand
  logoUrl       text nullable
  heroImageUrl  text nullable
  presetsMinor  json  $type<number[]>      // e.g. [500,1000,2500,5000]
  allowCustom   boolean default true
  frequencies   json  $type<Frequency[]>   // subset of ['one_time','monthly','roundup']
  createdBy     text -> user.id
  createdAt / updatedAt  timestamp
  // index: (organizationId), (status), (slug)

donation
  id            text pk
  reference     text unique                // human ref on receipt, e.g. 'MFB-7QX3'
  campaignId    text -> campaign.id
  organizationId text                      // denormalised for filtering
  donorName     text nullable              // null => 'Guest'
  donorEmail    text nullable
  amountMinor   integer
  currency      text
  frequency     text                       // 'one_time'|'monthly'|'roundup'
  status        text  // 'completed'|'pending'|'failed'
  source        text  // 'web'|'kiosk'
  paymentRef    text                       // links to processor settlement
  createdAt     timestamp
  // index: (campaignId), (organizationId), (status), (currency), (createdAt), (paymentRef)

processor_settlement   // MOCK external processor feed (reconciliation source B)
  id            text pk
  paymentRef    text
  amountMinor   integer
  currency      text
  status        text  // 'settled'|'failed'
  processedAt   timestamp

audit_log
  id            text pk
  actorId       text -> user.id
  actorEmail    text
  action        text                       // enum, see §7.6
  targetType    text nullable              // 'campaign'|'user'|'ledger'|...
  targetId      text nullable
  metadata      json nullable
  createdAt     timestamp
  // index: (createdAt), (actorId), (action)
```

`processor_settlement` is seeded to mostly mirror `donation.paymentRef` but with **deliberate discrepancies** (§9) so reconciliation has real mismatches. Live donations create a matching settlement on success, so new gifts reconcile clean.

## 5. Auth & RBAC (BetterAuth)

### 5.1 Instance (`auth.ts` — keep free of Elysia imports so the CLI can read it)
```ts
betterAuth({
  database: drizzleAdapter(db, { provider: 'sqlite' }),
  emailAndPassword: { enabled: true },
  user: { additionalFields: { organizationId: { type: 'string', required: false } } },
  plugins: [ admin({ ac, roles: { viewer, manager, admin } }) ],
})
```

### 5.2 Access control (admin plugin)
Define statements and roles with BetterAuth's access-control helper:

```
resources/actions:
  campaign       : read, create, update, delete
  donation       : read, export
  reconciliation : read, run
  audit          : read
  user           : read, manage        // set-role, ban
```

| Role | campaign | donation | reconciliation | audit | user |
|---|---|---|---|---|---|
| **viewer** | read | read | read | read | – |
| **manager** | read, create, update | read, export | read, run | read | – |
| **admin** | read, create, update, delete | read, export | read, run | read | read, manage |

(One org per user via `organizationId`; managers/admins act within their org. Platform-wide super-admin = an `admin` with no org filter — optional.)

### 5.3 Elysia integration (`plugins/better-auth.ts`)
```ts
const betterAuthPlugin = new Elysia({ name: 'better-auth' })
  .mount(auth.handler)                       // exposes /api/auth/*
  .macro({
    auth: {                                   // require a session
      async resolve({ status, request: { headers } }) {
        const s = await auth.api.getSession({ headers })
        if (!s) return status(401)
        return { user: s.user, session: s.session }
      },
    },
    permissions(required /* e.g. { campaign:['update'] } */) {  // require permission
      return {
        async resolve({ status, request: { headers } }) {
          const ok = await auth.api.hasPermission({ headers, body: { permissions: required } })
          if (!ok.success) return status(403)
        },
      }
    },
  })
```
Routes opt in per-route: `{ auth: true, permissions: { campaign: ['create'] } }`.
**Gotcha:** on some Elysia versions `.mount(auth.handler)` 404s sub-routes — if so, fall back to explicit catch-alls: `.get('/api/auth/*', ({request}) => auth.handler(request))` + `.post(...)`. Do **not** apply a JSON body parser before the auth handler.

### 5.4 Web auth client
Use BetterAuth's Solid client (`better-auth/solid`): `createAuthClient({ baseURL: VITE_API_URL })` → `signIn.email`, `signOut`, `useSession()`. Session cookie flows via `credentials: 'include'`. Guard admin routes in the router with a `useSession` check; also enforce server-side (never trust the client).

## 6. API contract

Base: `/api`. All non-auth responses JSON. **Error envelope** (every failure):
```json
{ "error": { "code": "VALIDATION"|"UNAUTHORIZED"|"FORBIDDEN"|"NOT_FOUND"|"PAYMENT_DECLINED"|"CONFLICT", "message": "human text", "fields"?: { "field": "reason" } } }
```
List conventions: `?page=1&pageSize=25&sort=createdAt&dir=desc` + resource filters; list responses `{ rows: T[], total, page, pageSize }`.

### 6.1 Public (no auth)
| Method | Path | Body / query | Returns | Behaviour |
|---|---|---|---|---|
| GET | `/campaigns` | `?status=active` | `CampaignPublic[]` | discover (active only) |
| GET | `/campaigns/:slug` | – | `CampaignPublic & { progress }` | branding, presets, frequencies, `{ raisedMinor, targetMinor, donorCount }` |
| POST | `/campaigns/:slug/donations` | `CreateDonation` | `{ reference, status, donation }` | **simulated payment** (§7.1); 402 on decline; on success persist + settlement + emit event |
| GET | `/campaigns/:slug/donations/:reference` | – | `DonationReceipt` | receipt data for `/thanks` |
| GET | `/config/currencies` | – | `{ base:'EUR', currencies:[…], rates:{…} }` | for the currency switcher (§7.4) |

`CreateDonation` = `{ amountMinor:int>0, currency:enum, frequency:enum, donorName?, donorEmail?, source:'web'|'kiosk', card?: { last4 } }`.

### 6.2 Auth
`ALL /api/auth/*` → BetterAuth (sign-in/out, session, admin ops).

### 6.3 Admin (auth + permission)
| Method | Path | Perm | Returns / behaviour |
|---|---|---|---|
| GET | `/admin/dashboard` | `donation:read` | `DashboardStats` (§7.3): totals per currency + EUR-equiv, counts, active campaigns, top campaigns, recent donations, trend series |
| GET | `/admin/campaigns` | `campaign:read` | paginated list (`?status,q`) |
| POST | `/admin/campaigns` | `campaign:create` | create (validate); audit `campaign.create` |
| GET | `/admin/campaigns/:id` | `campaign:read` | detail + campaign stats |
| PUT | `/admin/campaigns/:id` | `campaign:update` | update; audit `campaign.update` |
| DELETE | `/admin/campaigns/:id` | `campaign:delete` | delete; audit `campaign.delete` |
| GET | `/admin/donations` | `donation:read` | ledger; filters `campaignId,currency,status,source,dateFrom,dateTo,q`; sort; paginate |
| GET | `/admin/donations/export.csv` | `donation:export` | streams CSV (all filtered rows, capped); audit `ledger.export.csv` |
| GET | `/admin/reconciliation` | `reconciliation:run` | runs diff (§7.2) → `ReconciliationResult`; audit `reconciliation.run` |
| GET | `/mock-processor/settlements` | (internal) | returns `processor_settlement` rows — the external feed reconciliation reads |
| GET | `/admin/audit` | `audit:read` | audit log; filters `action,actorId,dateFrom,dateTo`; paginate |
| GET | `/admin/users` | `user:read` | list users (org-scoped) |
| PATCH | `/admin/users/:id/role` | `user:manage` | set role via BetterAuth admin API; audit `user.role_change` |
| POST | `/admin/audit/client-event` | `donation:read` | records a fixed enum of client-side actions (e.g. `ledger.export.pdf`) — restricted enum only |
| GET | `/admin/events` | `donation:read` | **SSE** stream (§7.7): `donation.created`, `reconciliation.updated`, heartbeat |

## 7. Domain behaviours

### 7.1 Simulated payment
On `POST …/donations`:
1. Validate (`amountMinor>0`, currency ∈ supported, frequency ∈ campaign.frequencies, campaign `active`). Invalid → `400 VALIDATION`.
2. **Deterministic demo failure:** if `card.last4 === '0002'` → `402 PAYMENT_DECLINED` (drives the error path M1.6). Otherwise proceed.
3. Generate unique `reference` (`<CAMP>-<base36×4>`, CAMP = campaign initials) and `paymentRef` (uuid).
4. Persist `donation{ status:'completed' }`; insert matching `processor_settlement{ status:'settled' }`.
5. Emit `donation.created` (§7.7). Return receipt.
6. Optional: honour an `Idempotency-Key` header to make retries safe.

### 7.2 Reconciliation algorithm
Inputs: completed `donation` rows (source A) + `GET /mock-processor/settlements` (source B). Full-join on `paymentRef`:
- **matched** — same `paymentRef`, equal `amountMinor` **and** `currency`, both success.
- **mismatched** — same `paymentRef`, but amount/currency/status differ.
- **missingInProcessor** — donation with no settlement.
- **missingInApp** — settlement with no donation.

Return `{ summary: { matched, mismatched, missingInProcessor, missingInApp }, rows: ReconRow[] }`. Each `ReconRow` carries status + both sides' values for drill-in. Audit `reconciliation.run`.

### 7.3 Multi-currency & dashboard totals
- Donations store their own `currency`. Config exposes `EUR` base + static `rates` (`{ EUR:1, USD:1.08, GBP:0.85 }` — hardcode in `lib/currency`).
- `toEURMinor(amountMinor, currency)` for aggregation. Dashboard shows **EUR-equivalent total** + a **per-currency breakdown** (never silently sum mixed currencies).
- Formatting is **frontend-only** via `Intl.NumberFormat(locale, { style:'currency', currency })`. Money cells use `font-variant-numeric: tabular-nums`.

### 7.4 Currency on the donor flow
Campaign has a base currency; the donor page offers a currency switcher (`/config/currencies`). Switching reformats presets using `rates`; the donation is recorded in the **chosen** currency and `amountMinor`.

### 7.5 Exports
- **CSV** — server `export.csv`, respects current filters, no pagination (cap ~50k), `Content-Disposition: attachment`. Audited server-side.
- **PDF** — client-side (`jsPDF` + `jspdf-autotable`) from the loaded, filtered ledger; on generate, `POST /admin/audit/client-event { action:'ledger.export.pdf' }` to record it.

### 7.6 Audit — record every admin mutation
Enum: `campaign.create|campaign.update|campaign.delete|user.role_change|reconciliation.run|ledger.export.csv|ledger.export.pdf|auth.login`. Write in the service layer of each mutation (not the route) with `{ actorId, actorEmail, action, targetType, targetId, metadata }`. (Login can be recorded via a BetterAuth hook.)

### 7.7 Real-time (SSE)
`plugins/events.ts` = in-memory subscriber set + `emit(event, data)`. `GET /admin/events` returns `text/event-stream`, registers the connection, sends a heartbeat comment every ~20s, cleans up on close. Payloads:
```
event: donation.created
data: { reference, campaignId, campaignName, amountMinor, currency, source, createdAt }
```
Client consumes with `new EventSource(`${API}/api/admin/events`, { withCredentials: true })` (cookie session ⇒ works cross-origin with CORS credentials). On message: bump counters, prepend to the recent-donations feed, push a point to the trend chart. Reconnect on error.

### 8.2 Theming & accessibility (implement against the design kit)
- Paste the kit's tokens into `styles/tokens.css` as CSS variables, defining **light** and **high-contrast** themes.
- `<html data-theme="light|contrast" data-textsize="100|112|125">`; contrast overrides via `[data-theme="contrast"]`.
- Text scaling: `:root{font-size:16px}` `[data-textsize="112"]{font-size:18px}` `[data-textsize="125"]{font-size:20px}` — everything in `rem`, no fixed heights on text containers.
- **Brand injection (donor app only):** set `--brand` (and a readable `--brand-fg` computed for contrast) from `campaign.brandColor` on the donor root. Prove it re-skins by rendering two campaigns.
- Persist theme / text-size / locale in `localStorage`.
- Floor: visible keyboard focus, `prefers-reduced-motion` respected, ≥44px targets on the donor app, AA contrast (AAA in high-contrast). Never rely on colour alone — pair status colour with icon + label (reconciliation, donation status).

### 8.3 i18n
`@solid-primitives/i18n` flat dictionary; `en` complete, `mt` partial (translate a coherent subset — nav, donor flow, dashboard labels). Locale in a signal + `localStorage`. All user-facing strings come from the dictionary; **never** bake text into images. Layout must tolerate ~30% expansion.

### 8.4 Validation
Server (Elysia `t`) is the source of truth; mirror the same shapes in valibot on the client for instant field errors. Key schemas: `CreateDonation`, `CampaignInput`, login. Errors surface in the interface's voice (active, specific — see the design brief's copy rules).

## 12. Integration notes & gotchas

- Keep `auth.ts` **free of Elysia imports** or `@better-auth/cli generate` can't read the config.
- Do **not** run a JSON body parser before the BetterAuth handler (client calls hang otherwise).
- If `.mount(auth.handler)` 404s sub-routes on your Elysia version, use explicit `GET/POST /api/auth/*` catch-alls.
- CORS must set `credentials: true` and the exact `WEB_ORIGIN`; the web client and EventSource must send credentials.
- `drizzleAdapter` provider is `sqlite` for libSQL/Turso.
- Money is **integer minor units** end-to-end; format only at the view. Never store or compute with floats.
- Recharts is React-only — use Chart.js in Solid.
- No secrets in the client; the web app only holds `VITE_API_URL`.
- README must include the demo accounts and the one-command run (`bun run dev` for both apps) so a judge can start it.
